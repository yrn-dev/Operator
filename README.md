# operator

## CLI 1.3: возможности десктопа в терминале

В 1.3.1 уточнены роль и характер Operator, добавлены реальные сведения об ОС,
CPU и RAM; `system_info` проверяет текущие ресурсы и, по запросу, NVIDIA GPU.
Старт CLI чистый по умолчанию; подробности доступны с `--verbose`.
Каталог скиллов в системном запросе сокращён, полные файлы скиллов сохранены.
Повторы одинаковых ошибок распознаются раньше; полезная длительная работа
не ограничена числом шагов.

История, настройки и память CLI хранятся на устройстве. При использовании
облачной модели запрос и переданный контекст отправляются её провайдеру.
Локальное хранение не означает, что сетевой запрос виден только владельцу.

Встроенные инструменты `subagent`, `background_run`, `background_check`,
`background_stop`, `github`, `browser`, `computer` и `system_info` загружаются автоматически.
Плагины и MCP из десктопа не переносятся. Qwen работает с включёнными
рассуждениями; переключателя thinking/no-thinking нет. Модели без поддержки
reasoning продолжают работать в своём обычном режиме.

```bash
operator --doctor                  # проверка окружения без обращения к модели
operator                           # интерактивный терминал
operator --autopilot                # явно разрешить браузер и экран на этот запуск
operator -p "проверь проект"       # одноразовый запуск
```

| Команда в диалоге | Возможность |
| --- | --- |
| `/features` | Список новых команд |
| `/autopilot on` / `/autopilot off` | Включить/выключить браузер и управление экраном |
| `/jobs`, `/jobs ID`, `/jobs stop ID` | Фоновые процессы, последние строки лога, остановка |
| `/agents` | Задачи, действия и результаты субагентов |
| `/chat new ЗАДАНИЕ` | Начать независимый диалог, пока текущий остаётся открытым |
| `/chat list`, `/chat show ID` | Статусы открытых диалогов и их результаты |
| `/chat send ID ТЕКСТ`, `/chat answer ID` | Уточнить задачу или ответить на запрос разрешения |
| `/chat stop ID`, `/chat open ID`, `/chat close ID` | Остановить работу, открыть сохранённый диалог, закрыть процесс |
| `/undo` | Откат последнего `write`/`edit`/`patch`, включая многофайловую правку |
| `/changes`, `/changes N` | История файловых правок и diff до/после |
| `/permissions` | Правила разрешений |
| `/permissions allow bash ТОЧНАЯ КОМАНДА` | Разрешить конкретную команду с её аргументами |
| `/permissions deny bash ТОЧНАЯ КОМАНДА`, `/permissions remove N` | Запретить действие или удалить правило |
| `/doctor` | Проверить окружение текущей сессии |
| `/keys` | Ввести скрытый ключ, заменить или удалить его |
| `/sound on`, `/sound off`, `/sound volume 50`, `/sound test` | Звуки завершения и запроса ввода |
| `/rename НАЗВАНИЕ`, `/compact` | Название диалога и сжатие контекста |
| `/hooks` | Посмотреть настроенные команды на события |

Название нового диалога берётся из первой реплики локально, без дополнительного
запроса к модели. История и экспорт остаются
доступны через `/resume` и `/export`. Вложения передаются через `@путь`, а
изображения можно вставлять средствами поддерживаемого терминала.

Браузер запускает отдельный профиль Chrome/Chromium, не читает личный профиль.
Поддерживает формы, выбор значений, загрузку явно указанных файлов и ожидание
текста. Если браузер не найден, задайте `OPERATOR_BROWSER_EXECUTABLE`.
Для режима без окна: `OPERATOR_BROWSER_HEADLESS=1`. Для экранного ввода нужны
системные средства (`xdotool` на X11, `ydotool` на Wayland и т. п.);
`operator --doctor` показывает доступные средства. Автопилот по умолчанию выключен.

Субагенты наследуют выбранную модель и провайдера; по умолчанию им доступны
только инструменты чтения. Открытые через `/chat` процессы завершаются при
выходе из CLI, но их история сохраняется. Фоновые shell-процессы отделены от
диалога; управляйте ими до закрытия текущего CLI.

Настройки разрешений, звука и хуков: `~/.opr/agent/native/policy.json`.
Копии файлов и записи правок: `~/.opr/agent/native/checkpoints/`.
Откат не затирает последующие внешние изменения. Изменения через shell, API
или интерфейс приложений не входят в файловые checkpoints. Проверка опасных
команд — проверка известных шаблонов, а не системная песочница.

Хуки задаются пользователем в `policy.json`, например:
`"hooks": [{"event":"agent_end","command":"your-command"}]`.
Поддержаны `tool_result` и `agent_end`, необязательные `tool` и `cwd`.

Ядро заранее сжимает контекст, восстанавливает локальную сводку при сбое,
сокращает старые большие результаты в запросе с сохранением оригиналов,
выявляет повторяющиеся ошибки и продолжает ответ при достижении лимита вывода.

Проверки: `npm test` и `npm run check:compaction`. Используются временные файлы,
локальный тестовый сервер и отдельный профиль браузера; реальные ключи не нужны.

Личный агент для работы с кодом в терминале — свой аналог Claude Code, но на моделях Alem AI (`llm.alem.ai`) плюс всё, что крутится локально в Ollama. Читает и правит файлы, гоняет bash, помнит задачи и факты между сессиями, коммитит в git. Пакет называется `pzero-operator`, бинарник — `operator` (или короче: `opr`).

```bash
npm install -g pzero-operator
operator
```

Если npm недоступен, CLI можно установить напрямую из GitHub Release:

```bash
npm install -g https://github.com/yrn-dev/Operator/releases/download/v1.3.3/pzero-operator-1.3.3.tgz
```

Пакет: [pzero-operator](https://www.npmjs.com/package/pzero-operator) · репозиторий: [yrn-dev/Operator](https://github.com/yrn-dev/Operator)

## Запуск

```bash
operator                          # интерактивный TUI
operator -p "напиши тесты"        # одноразовый запрос, без TUI
operator --continue                # продолжить последнюю сессию
operator --resume                  # выбрать сессию из списка
operator --list-models             # что вообще доступно
```

## Модели

По умолчанию — `qwen3-8`, 262K контекста, тянет картинки. И по вайб-кодингу и качеству кода сейчас реально обходит Opus 4.6 (max) — не маркетинг, проверено на своих задачах.

| Модель | Контекст | Картинки |
|---|---|---|
| `qwen3-8` | 262K | да |
| `gemma4` | 252K | да |
| `gpt-oss` | 128K | нет |

Плюс всё, что найдётся на `localhost:11434` — это Ollama, и не только локальные веса: с недавних пор она сама умеет проксировать облачные модели (`ollama signin`, модели с суффиксом `:cloud`) через тот же локальный API, так что список моделей может быть внушительным, даже если у тебя не крутится ничего тяжелее ноутбука. Подхватывается сам при старте, без конфига — и локальное, и облачное одинаково.

Ключ Alem AI лежит в `~/.opr/agent/auth.json`:

```json
{"alem-ai":{"type":"api_key","key":"sk-..."}}
```

или просто `export ALEM_AI_API_KEY=sk-...`. Модельный реестр и переопределения контекстов — в `~/.opr/agent/models.json`, если что-то надо докрутить руками (провайдер, свой `baseUrl`, лимиты).

## В интерактиве

- `/model` — переключить модель на лету
- `/status` — модель, провайдер, шкала заполнения контекста и реальный расход токенов (вход/выход/кэш) за сессию
- `/new`, `/resume` — новая сессия / выбрать старую
- `/export`, `/import` — сессия в JSON и обратно
- `!команда` — bash прямо из чата, `!!команда` — то же самое, но не попадёт в контекст

## Инструменты агента

Из коробки: `read` / `write` / `edit` файлов, `bash`, `git_status` / `git_diff` / `git_commit`, `test_run` (сам определяет фреймворк — npm/pytest/cargo/go/gradle/dotnet), веб-поиск, и пара штук для долгой памяти между сессиями — `task_plan`/`task_update`/`task_list` под план работы, `memory_store`/`memory_recall` под факты (`~/.opr/agent/memory/*.md`, `~/.opr/agent/tasks.json`).

Системный промпт можно полностью заменить: `~/.opr/agent/SYSTEM.md` — глобально, `<проект>/.opr/SYSTEM.md` — под конкретный репозиторий (только для trusted-проектов). `APPEND_SYSTEM.md` рядом — не заменяет, а дописывает поверх.

## Флаги, которые реально нужны

| Флаг | Что делает |
|---|---|
| `--model <id>` | конкретная модель вместо дефолтной |
| `--provider ollama` | всё через локальную Ollama |
| `-p`, `--print` | без TUI, разовый прогон |
| `-c`, `--continue` | продолжить сессию |
| `--name "..."` | назвать сессию, чтобы потом найти |
| `--offline` | без сети вообще (проверки апдейтов, веб-поиск и т.п. отключены) |

Остальное — `operator --help`.

## Сессии

Лежат в `~/.opr/agent/sessions/`, по одному jsonl-файлу на сессию, автосейв на каждом шаге. `--fork` берёт существующую сессию и продолжает её в новую, не трогая оригинал.

## Десктоп-версия

Есть и GUI: [Operator Desktop](https://github.com/yrn-dev/operator-desk) — Electron-приложение, которое поднимает `opr --mode rpc` и рисует сам: сессии, живая лента, вложения, плагины. Этим репо живёт CLI (`pzero-operator`), Desktop-версия — в отдельном репо [yrn-dev/operator-desk](https://github.com/yrn-dev/operator-desk) (сборка под macOS/Linux/Windows — в его `BUILD.md`).
